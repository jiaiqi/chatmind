## 二、待完善功能清单

### 2.1 已知缺陷（建议优先修复）

#### 1. 报告导出脱敏开关未生效
- **现状**: `ReportExportView.vue` 中 `sanitizeEnabled` 有完整的 UI 开关，但 `handleExportImage` / `handleExportPDF` 函数完全没有读取该值，也未调用 `src/ai/sanitizer.ts` 中的脱敏函数
- **影响**: 用户开启"隐私脱敏"后，导出的报告仍包含原始敏感信息，开关是摆设
- **涉及文件**: `src/views/ReportExportView.vue`, `src/utils/export.ts`
- **状态**: 🔴 待修复

#### 2. Store `isLoading` 未使用
- **现状**: `sessionStore` 中定义了 `isLoading` 全局状态，但 DashboardView、TimelineView、AnalysisView 等视图各自维护独立的 `isLoading` ref，未复用 store 中的统一状态
- **影响**: 代码重复，全局加载状态不可控
- **涉及文件**: `src/stores/session.ts`, `src/views/` 各视图
- **状态**: 🟡 待优化

---

### 2.2 高价值 · 低复杂度（推荐近期优先）

#### 3. 更多示例数据
- **需求来源**: 当前仅 1 种恋爱故事示例
- **说明**: 增加职场（同事协作/上下级）、亲情（父母子女）、友情（闺蜜/兄弟）三种关系类型的示例数据
- **价值**: 让新用户零成本体验不同场景，降低首次使用门槛
- **涉及文件**: `src/utils/demo-data.ts`
- **状态**: ⏳ 待开发

#### 4. 参与者详情展示
- **现状**: `sessionStore.getParticipants()` 已写好但没有任何视图调用，`firstSeen` / `lastSeen` / `messageCount` 等数据已计算并存入数据库
- **说明**: 在侧边栏或消息列表旁增加"参与者信息"面板，展示双方的首次/最后出现时间、消息总数、活跃天数
- **涉及文件**: `src/components/AppLayout/AppLayout.vue` 或新建组件
- **状态**: ⏳ 待开发

### 2.3 技术债务与工程化

#### 5. 单元测试覆盖
- **现状**: PROJECT_STATUS 标记为"未解决"
- **范围**: parsers（格式解析正确性）、analyzers（统计计算准确性）、identity（身份识别逻辑）
- **工具**: Vitest
- **优先级**: 中。 analyzers 逻辑已趋于稳定，适合补充测试
- **状态**: ⏳ 待开发

#### 6. 清理未使用依赖
- **现状**: `package.json` 中安装了 `jszip`、`superjson`、`date-fns-tz`、`highlight.js`、`lodash`、`lodash-es` 及对应 `@types`，但代码中没有任何 import
- **影响**: 增加安装体积和攻击面，造成维护困惑
- **涉及文件**: `package.json`
- **状态**: ⏳ 待清理

#### 7. ECharts 代码分割与懒加载
- **现状**: 生产包 2.4MB+，构建工具提示 chunk 过大
- **说明**: 将各视图的 ECharts 配置和组件改为按需加载（`import()`），非首屏图表延迟加载
- **涉及文件**: `vite.config.ts`、`src/views/` 各图表页面
- **优先级**: 低。当前是桌面/Web 应用，2MB 在现代网络下可接受
- **状态**: ⏳ 待开发

#### 8. 大数据性能优化
- **现状**: 消息列表分页 50 条，未做虚拟滚动
- **说明**:
  - 消息列表虚拟滚动（`vue-virtual-scroller`）
  - 导入大文件（>100MB）分块解析 + Web Worker
  - 图表数据点超过 1000 时降采样
- **优先级**: 低。当前用户场景下消息量通常几万条，IndexedDB 可承受
- **状态**: ⏳ 待开发

### 2.3 长期愿景（Phase 3+）

#### 5. Electron 桌面端封装
- **说明**: 打包为桌面应用，可对接 WeFlow HTTP API（127.0.0.1:5031）直连读取微信数据库，无需手动导出文件
- **依赖**: WeFlow 需先支持 HTTP API
- **优先级**: 低。当前 Web 版已能跑通完整流程
- **状态**: ⏳ 待开发

#### 6. 群聊分析模式
- **说明**: 多人身份识别、群体情绪趋势、"潜水王"/"话痨"排行、小团体分析
- **优先级**: 低。PRD 中主要定位一对一关系分析
- **状态**: ⏳ 待开发

#### 7. 情感账户（积分模型）
- **说明**: 正向互动 +1 分（关心、赞美、及时回复），负向互动 -1 分（敷衍、延迟、争吵）。展示双方的情感账户余额变化
- **优先级**: 低。概念有趣，但规则设计复杂，容易失真
- **状态**: ⏳ 待开发

## 三、推荐优先级排序

### 近期（下个版本）—— 先修缺陷再补功能

| 序号 | 功能 | 原因 |
|------|------|------|
| 1 | 修复导出脱敏开关未生效 | 真实 Bug，用户开启开关后仍导出敏感信息 |

| 序号 | 功能 | 原因 |

## 四、与竞品差异化对照

| 维度 | ChatLab | WeFlow | ChatMind 当前 |
|------|---------|--------|---------------|
| 身份识别 | ❌ 混乱 | ⚠️ 仅导出 | ✅ 多层确认 + 消息级校准 |

| AI 交互 | Agent + SQL | 无 | ✅ 流式问答 + Function Calling + 可溯源 |
| 可溯源 | ❌ | 无 | ✅ AI 回答引用原文 + 时间轴下钻 |
| 报告导出 | 无 | 年度报告 | ✅ PDF + 图片 + 事件标记故事线 |

## 五、结论

当前 v0.2.0 已覆盖 MVP 全部核心功能和 Phase 2 的绝大部分增强功能。产品在"数据展示 → AI 分析 → 关系洞察"的完整链路上已经闭环。

**下一个版本建议聚焦"体验完善 + 工程化"**：

1. **更多示例数据**（降低首次使用门槛）
2. **单元测试覆盖**（为后续重构和扩展保驾护航）

在这两项完成后，ChatMind 的 v0.2.x 可以视为一个功能完整、体验成熟的产品版本，后续可进入 Phase 3 的长期愿景探索。
