# ChatMind - AI 微信聊天记录分析工具

## 产品需求文档 (PRD)

> 版本: v0.2.0  
> 日期: 2026-05-16  
> 状态: 已交付 / 持续迭代

---

## 一、项目背景

### 1.1 市场现状
- **ChatLab**: 开源本地 AI 聊天记录分析工具，支持多平台导入，AI Agent + SQL 双引擎。但存在**身份识别混乱**（分不清"我"和"对方"）、分析结果泛泛而谈等问题。
- **WeFlow**: 微信本地数据导出工具，可直接解密 PC 微信数据库，导出多格式数据，含朋友圈导出。但 AI 分析能力弱。

### 1.2 机会点
做"**ChatLab 的分析深度 + WeFlow 的数据获取能力**"，并**彻底解决身份识别问题**，打造一款专注于"关系分析"的垂直 AI 工具。

### 1.3 产品定位
> **ChatMind** - 用 AI 读懂你们的关系

- **本地优先**：所有数据处理在本地完成，聊天记录不上传云端
- **关系导向**：不做通用聊天分析，专注分析"人与人之间的关系状态"
- **可溯源**：每个 AI 结论都可以点击追溯到原始聊天记录

## 三、核心功能模块

### 3.1 数据导入 (Import)

#### 3.1.1 导入路径（优先级排序）

```
路径 A（最深，体验最好）─── WeFlow 直连模式 [P2]
  ├─ 检测用户是否已安装/运行 WeFlow
  ├─ 调用 WeFlow 的 HTTP API (127.0.0.1:5031) 直接读取
  ├─ 自动拉取联系人列表、选择对话、同步消息
  └─ 优势：实时、完整、wxid/昵称映射准确

路径 B（推荐，最稳）────── WeFlow 导出文件导入 [P0]
  ├─ 用户在 WeFlow 中导出 JSON/CSV/ChatLab格式
  ├─ 拖拽导入你的应用
  ├─ 解析时读取元数据（WeFlow导出的文件可包含wxid）
  └─ 优势：一次导出、离线分析、可分享

路径 C（兼容）────────── 通用格式导入 [P1]
  ├─ 支持微信官方备份、其他第三方工具导出的格式
  ├─ TXT、HTML、JSON、CSV
  └─ 劣势：wxid可能缺失，身份识别更依赖用户手动标记
```

#### 3.1.2 导入流程

```
[选择导入方式]
     ↓
[上传文件 / 连接 WeFlow]
     ↓
[解析数据 ── 显示联系人列表]
     ↓
【关键步骤】身份确认弹窗
  ├─ "请选择你的身份"
  ├─ 列出所有参与者（昵称 + wxid）
  ├─ 支持勾选"这是我"、"这是对方"
  ├─ 支持填写"我的曾用名"（历史昵称）
  └─ 支持"不确定，稍后标记"
     ↓
[数据清洗与入库]
     ↓
[进入分析仪表盘]
```

### 3.2 身份识别系统 (Identity) [核心卖点]

#### 3.2.1 问题定义
微信聊天记录中，用户的身份标识可能随时间变化：
- 用户改了微信昵称
- 用户在不同群聊中显示不同昵称
- 备注名 vs 微信昵称
- 导出文件中缺少 wxid

#### 3.2.2 解决方案：多层身份确认机制

**第一层：用户主动声明（最准确）**
- 导入时弹出对话框："请选择你的身份"
- 支持按昵称、备注名、wxid 多维度标记
- 支持"我曾用名"：一个人可能改过微信名
- 群聊场景：用户可标记多个"自己"的身份

**第二层：智能辅助识别（降低用户操作成本）**
- 系统消息推断："你已添加XXX" → "你"就是用户
- 发言特征推断：文件传输助手对话中的发送方
- 时间规律推断：辅助判断

**第三层：导入后校准（兜底修正）**
- 在对话预览中高亮显示"已标记为你"的消息
- 一键切换：发现标记错了，点击"这是我的消息/这是对方的消息"
- 全局修正：把某个昵称的所有消息批量归给用户/对方

#### 3.2.3 身份识别实现

当前版本采用简化方案，身份映射直接由 `src/stores/identity.ts` 管理：

- 用户确认的 `senderId → role` 映射存储在 Pinia Store 中
- 曾用名信息存储于 `DbParticipant.names` 数组中
- 运行时通过 `names` 数组匹配处理改名场景

> 未来如需更复杂的身份图谱（如 wxid 到多昵称的时间线映射），可在此基础上扩展。

### 3.3 数据分析引擎 (Analysis)

#### 3.3.1 分析维度

**基础层（统计型）**
| 指标 | 说明 |
|------|------|
| 消息量对比 | 谁主动多、谁回复快 |
| 回复延迟热图 | 冷暴力的数字证据 |
| 消息长度趋势 | 从长篇大论到"嗯""哦" |
| 聊天时段迁移 | 从深夜畅聊到白天敷衍 |
| 表情包情绪替代率 | 文字越来越少，表情包越来越多 |

**进阶层（情绪型）**
| 指标 | 说明 |
|------|------|
| 单条消息情绪 | 正面 / 负面 / 中性 / 暧昧 / 愤怒 / 委屈 |
| 对话轮次情绪 | 一方负面时，另一方是安抚还是对抗？ |
| 情绪感染度 | 负面情绪是否快速传染？ |
| 情绪修复时间 | 一次争吵后，多久恢复正面交流？ |
| "已读不回"指数 | 发出消息后对方多久回复，是否越来越慢 |

**高阶层（关系型）**
| 指标 | 说明 |
|------|------|
| 亲密度曲线 | 综合消息频率、深度、情绪正向度 |
| 权力不对等 | 谁主导话题、谁经常妥协 |
| 情感账户 | 正向互动+分，负向互动-分 |
| 关系阶段判定 | 蜜月期→稳定期→倦怠期→危机期 |

#### 3.3.2 危险信号检测

- 长时间单方输出（倾诉不对等）
- 情绪价值单向索取
- "分手""离婚""烦"等词汇频率突增
- 热情-回应比持续走低
- 连续 N 天无有效交流

### 3.4 AI 分析系统 (AI Agent)

#### 3.4.1 分层架构

```
预处理层（本地规则 + 轻量模型）
  ├─ 中文分词 + 情感词典（正面/负面词库）
  ├─ 表情包 → 情绪映射（😂=正面，😭=负面，🙄=敷衍）
  ├─ 标点特征：问号数量、感叹号、省略号...
  └─ 输出：每条消息的"基础情绪标签"

AI 层（调用大模型，做聚合分析）
  ├─ 输入：一段时间的消息聚合（不是单条）
  ├─ 任务：总结这段关系的整体状态、给出洞察
  └─ 例如："最近30天，A方情绪明显走低，B方回应变得简短..."

交互层（AI Agent）
  ├─ 用户提问："我们最近是不是出问题了？"
  ├─ 系统调用工具查询对应指标 → 生成回答
  └─ 引用具体消息作为证据（可溯源）
```

#### 3.4.2 支持的 AI 模型

| 提供商 | 代表模型 | 类型 |
|--------|----------|------|
| DeepSeek | V3, R1 | 云端 |
| Kimi (月之暗面) | 8K / 32K / 128K | 云端 |
| MiniMax | abab6.5 / abab7 | 云端 |
| 百炼 (阿里云) | 通义千问 Plus/Max/Turbo/Coder | 云端 |
| SiliconFlow | DeepSeek V3/R1, Qwen2.5 | 云端 |
| 智谱 AI (GLM) | GLM-4 / Flash / Air / Plus | 云端 |
| 百度千帆 | 文心 4.0 Turbo / 3.5 / Speed | 云端 |
| 腾讯云 (混元) | Turbo / Pro / Standard | 云端 |
| Ollama | qwen2.5:7b/14b, deepseek-r1:7b, llama3.2 等 | 本地 |
| 自定义 | 任意 OpenAI 兼容端点 | 云端/本地 |

### 3.5 可视化与报告 (Visualization)

#### 3.5.1 核心页面

**1. 关系时间轴（核心页面）**
- 横轴：时间
- 纵轴：情绪值（-1 ~ +1）
- 双曲线：你（蓝色）和对方（红色）
- 事件标记：争吵爆发点、和好时刻、危险信号、用户手动标记里程碑

**2. 对比视图**
- 并排对比双方的高频词云、情绪分布、主动发起次数、平均回复时间

**3. AI 报告页（可导出 PDF）**
- 数据概览
- 核心洞察（3-5 条）
- 需要关注的危险信号
- AI 建议

## 四、非功能需求

### 4.1 性能
- 支持百万级消息量的丝滑解析和查询
- 使用 Web Worker / 多线程处理重计算任务
- 虚拟滚动 + 分页加载处理长对话

### 4.2 隐私
- 所有数据处理在本地完成
- 调用云端 AI API 时，提供"脱敏模式"（替换昵称、去除敏感信息）
- 明确告知用户哪些数据会发送到云端

### 4.3 兼容性
- 支持微信 PC 版 4.0+
- 支持 WeFlow 导出的所有格式
- 支持主流浏览器（Chrome、Edge、Safari）

## 六、Roadmap

```
Phase 1（MVP）: 基础导入 + 身份识别 + 统计
  ├─ WeFlow JSON 导入
  ├─ 身份选择弹窗 + 曾用名支持
  ├─ 消息量、时间分布、词频统计
  └─ 目标：能跑通一条完整的聊天记录分析

Phase 2: 情绪分析
  ├─ 接入 AI API
  ├─ 单条/批量情绪标注
  └─ 情绪趋势曲线

Phase 3: 洞察报告
  ├─ AI 生成关系总结
  ├─ 危险信号检测
  └─ PDF 导出

Phase 4: 深度整合
  ├─ WeFlow HTTP API 直连
  ├─ Electron 桌面应用打包
  ├─ 本地 AI 模型支持（Ollama）
  └─ 高级可视化
```

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 微信数据库加密变更 | 高 | 依赖 WeFlow 更新，不自己维护解密逻辑 |
| AI 分析准确性不足 | 中 | 用规则做基础，AI 做聚合，不追求逐条精准 |
| 用户担心隐私 | 中 | 本地优先 + 开源 + 脱敏模式 |
| 情感分析结果伤人 | 中 | 添加免责声明 + 温和的表达方式 |
